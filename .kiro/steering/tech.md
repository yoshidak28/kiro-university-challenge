# 技術スタック・技術方針

## 技術スタック

- **言語**：HTML / CSS / バニラ JavaScript（ES5〜ES6 相当の構文）
- **音声**：Web Speech API（`window.speechSynthesis` / `SpeechSynthesisUtterance`）
- **フォント**：Google Fonts「M PLUS Rounded 1c」
- **フレームワーク・ライブラリ**：なし（ランタイム依存ゼロ）
- **ビルドツール**：なし（トランスパイル・バンドル不要）

## 重要な制約

- 外部の JavaScript / CSS フレームワーク、ランタイム依存を**追加しない**
  （タイポグラフィ用の web フォントのみ例外）。
- **ビルドステップを導入しない**。ソースをそのままブラウザで実行できる状態を保つ。
- `file://` プロトコルで直接開いても、静的ホスティング（GitHub Pages 等）に
  置いても、サーバーサイド処理なしで完全動作すること。
- ES Module 構文（`import` / `export`）は `file://` の CORS 制約を避けるため**使わない**。
  スコープ分離が必要な場合は IIFE やオブジェクトリテラルを用いる。

## コード構成の方針

- **純粋ロジックと DOM 操作を分離する**。
  - 出題・採点・評価などのロジックは副作用のない純粋関数として実装し、テスト容易性を確保する
    （例：`QuizLogic`）。
  - DOM 操作・イベントバインディングは View 層にまとめる（例：`QuizView`、`GojuonTableView`）。
- グローバル状態は 1 箇所に集約する（例：`AppState`）。
- 乱数を使う関数は、テスト用に乱数生成関数（`rng`）を注入できるようにする。

## 音声読み上げの指針

- 読み上げは日本語（`lang = 'ja-JP'`）で行う。
- 未就学児向けに、話速はやや遅め・ピッチはやや高めに設定する。
- 進行中の発話がある場合は、新しい発話の前にキャンセルする。
- Web Speech API 非対応ブラウザではサイレントにフォールバックし、
  音声以外の機能は動作を継続する。
- 読み上げ用テキストの助詞表記ルールは `speech-text.md` を参照（「は」→「わ」、「へ」→「え」）。

## アクセシビリティの指針

- WAI-ARIA のタブパターン（`role="tablist"` / `role="tab"` / `role="tabpanel"`）を用いる。
- 動的に更新される領域には `aria-live` を設定する。
- 進捗バーには `role="progressbar"` と `aria-valuenow/min/max` を設定する。
- `prefers-reduced-motion` が有効な環境では、アニメーション・トランジションを抑制する。
- タップターゲットは未就学児の指でも押しやすい十分な大きさを確保する。

## テスト・検証

- 純粋ロジックは、プロパティベーステスト（fast-check を想定）での検証を推奨する。
- 変更後は少なくとも `node --check` で各 JS ファイルの構文を確認する。
